# Android Vocabulary App: Implementation and Private Distribution

**Research date:** 2026-10-09

**Repository note:** This repository describes itself as a list of free developer services, so this app research is outside its stated scope. The requested note is isolated here; no application files are changed.

## Recommendation

For an Android-only family app, use **Kotlin + Jetpack Compose**, with curated word content bundled locally and learner/progress records in Room. Keep new-word limits, review scheduling, and scoring deterministic and independent of AI. Offer Gemini Nano prompt variations only when ML Kit reports the feature available; otherwise show the original curated content. This is the shortest path to ML Kit's Android API, and avoids making the core offline learning loop depend on device-specific GenAI support. Compose is Android's recommended native UI toolkit, and Room is Google's SQLite abstraction for structured local data ([Compose](https://developer.android.com/develop/ui/compose), [Room](https://developer.android.com/training/data-storage/room)).

For family delivery, prefer a **Google Play internal testing track** if setting up Play Console is acceptable: it supports up to 100 email-listed testers, distributes through Play, and new internal releases are generally available within minutes. Use a signed APK for a quick pilot or when avoiding Play Console matters more than convenient installs and updates. A Managed Google Play private app is for an organization managing Android devices, not a typical household.

## Implementation Options

| Option | Gemini Nano / ML Kit GenAI path | Fit for this app |
| --- | --- | --- |
| **Kotlin + Compose** | Call ML Kit's Android/Kotlin Prompt API directly. No framework bridge is needed. | Best fit for Android-only scope, local-first storage, and a small number of screens. Compose is Android-native; Room handles structured profiles, word history, settings, and due reviews. |
| **Flutter** | Implement a Kotlin Android plugin and call it from Dart using a platform channel; Flutter also documents Pigeon for generated, typed channel messages. | Good if a real iOS or other-platform app is planned and the team wants shared Dart UI/logic. Gemini Nano still needs Android-native integration, availability checks, and fallback handling. |
| **React Native** | Implement an Android native module in Kotlin/Java and expose it to TypeScript/JavaScript; the current Turbo Native Module path uses a typed spec and Codegen. | Good if the team already has a React Native/TypeScript product or skills. It still needs Android-native GenAI integration and adds a JS/native boundary. |

Flutter's and React Native's official docs explain general native integration; in the official materials reviewed, I found no first-party Flutter or React Native ML Kit GenAI client. That is **not confirmation that no community wrapper exists**. Framework bridge references: [Flutter platform channels](https://docs.flutter.dev/platform-integration/platform-channels), [React Native Turbo Native Modules](https://reactnative.dev/docs/turbo-native-modules-introduction). ML Kit's Prompt API is an Android API ([overview](https://developers.google.com/ml-kit/genai/prompt/android), [setup](https://developers.google.com/ml-kit/genai/prompt/android/get-started)).

For this scope, store the original 11+ word, definition, and example set as app content. Store per-learner preferences and progress locally (for example: profile, word ID, exposures/results, and next-due time). The review algorithm and configurable daily new-word count can operate without a network or a model. Android's offline-first guidance defines offline-first behavior as retaining core functionality without internet access ([guide](https://developer.android.com/topic/architecture/data-layer/offline-first)).

## Gemini Nano Availability and Fallbacks

- **API floor is not device support.** ML Kit Prompt API requires Android API level 26+, but that alone does not mean the device can run Gemini Nano. Google's current [GenAI device matrix](https://developers.google.com/ml-kit/genai#prompt-device) lists Prompt API devices by Nano model generation (`nano-v2`, `nano-v3`, `nano-v4`) and names selected Pixel and partner devices. It is not an all-Android-device capability; check the live matrix for exact models and variants.
- **Check runtime status before showing AI controls.** ML Kit returns `AVAILABLE`, `DOWNLOADABLE`, `DOWNLOADING`, or `UNAVAILABLE`; `UNAVAILABLE` can mean unsupported hardware or that the device has not fetched the latest configuration. The API supports requesting a download when offered ([setup/status handling](https://developers.google.com/ml-kit/genai/prompt/android/get-started)).
- **Offline inference has setup conditions.** Android documents that inference runs on-device and works offline, with model distribution/updates managed by AICore ([Gemini Nano / AICore](https://developer.android.com/ai/gemini-nano)). However, ML Kit notes that after device/AICore setup or reset, configuration may require internet and can take minutes to hours; model download also needs connectivity. Treat AI as unavailable until status says it is ready, and never block core learning on setup ([setup issues](https://developers.google.com/ml-kit/genai/prompt/android/get-started)).
- **Other constraints:** ML Kit Prompt API is beta and has no SLA or deprecation policy; it enforces a per-app inference quota and does not support devices with unlocked bootloaders ([Prompt API](https://developers.google.com/ml-kit/genai/prompt/android), [limitations and setup](https://developers.google.com/ml-kit/genai/prompt/android/get-started)). Preview model variants have additional device constraints and should not be assumed available in production ([model selection](https://developers.google.com/ml-kit/genai/prompt/android/select-model)).

**Practical use:** Keep AI to a short optional variation of an existing word/example, cap output length, validate the result, and fall back to curated text on any unavailable status or inference error. Do not let generated text define the vocabulary, change a learner's progress, or determine what is due. The Prompt API accepts custom text prompts and supports output controls; prompt quality and QA remain the app developer's responsibility ([Prompt API overview](https://developers.google.com/ml-kit/genai/prompt/android), [request setup](https://developers.google.com/ml-kit/genai/prompt/android/get-started)).

## Private Distribution

| Route | Benefits | Friction and caveats |
| --- | --- | --- |
| **Direct signed APK** | Simplest for a tiny, trusted pilot; no Play testing track or public listing. | APKs must be signed. Android permits updates only when the installed app and update have matching signing certificates, so preserve the key. Users install from the file/source and may see Play Protect scanning for apps from outside Play; sharing and updating each release is manual ([app signing](https://developer.android.com/studio/publish/app-signing), [unknown app installs](https://developer.android.com/about/versions/oreo/android-8.0-changes), [Play Protect](https://support.google.com/android/answer/2812853?hl=en)). |
| **Play internal testing** | Best low-friction family channel when a Play developer account is acceptable: up to 100 testers, Play installation/updates, and new releases typically reach testers within minutes. Testers need a Google account and must opt in. | Requires Play Console setup and a tester list/link. Google warns internal tracks might not receive standard policy/security review and are exempt from the Play Data safety section; it is a test track, not a private production listing ([internal/closed testing](https://support.google.com/googleplay/android-developer/answer/9845334?hl=en)). |
| **Play closed testing** | Controlled, opt-in audience via email lists or Google Groups; useful for a wider pilot or staged validation. | More tester/release administration than internal testing. If later seeking production access with a personal developer account created after 2023-11-13, Google currently requires a closed test with at least 12 testers opted in continuously for 14 days before applying. This requirement concerns production access, not a family-only test release ([testing requirements](https://support.google.com/googleplay/android-developer/answer/14151465?hl=en)). |
| **Managed Google Play private app** | Organization-restricted Play distribution and management. | Requires an organization/Organization ID and managed Android environment. It is intended for apps private to organizations, so it is generally a poor fit for an ordinary family ([publish private apps](https://support.google.com/googleplay/work/answer/6145139?hl=en)). |

**Choice:** Start with internal testing for convenient household installs and updates; choose direct APK for the fastest one-off trial if every family member can handle manual install/update steps. Use closed testing only when a larger controlled cohort or future production-access test is actually needed. Do not choose Managed Google Play unless the family has a genuine managed organization environment.

## Sources and Unconfirmed Points

All sources linked above are first-party Android, Google ML Kit, Flutter, React Native, or Google Play documentation. Device support changes over time; the linked matrix is the source of truth on the research date. The API-level floor does not establish availability on a particular handset, and no guarantee is made that a device will have completed model/configuration setup when first used. A specific community Flutter/React Native wrapper's quality or maintenance was not assessed.
